# ADR-0007 · 데스크톱 먼저, 메뉴 골격부터 작은 조각으로

- 상태: 확정 · 2026-10-29 (사용자 결정)
- 맥락: 웹·데스크톱을 같이 만들면 첫 화면이 늦다. 사용자: "작은 부분부터 눈에 보이게" · "기본 메뉴 구성 먼저, 하나씩 구체적으로" · "관리자 페이지도".
- 결정
  - 표면 순서: **데스크톱(Electron) 먼저**. 웹(`apps/web`)은 당분간 **랜딩 + 다운로드만**. 관리자 콘솔(`apps/admin`, 별도 SPA)은 메뉴 골격을 같이 만든다.
  - 진행: ① 메뉴 골격(메뉴마다 빈 화면) → ② 메뉴 하나씩 실제 구현. 화면 원본 = `design/prototype.html`.
  - 메뉴: 데스크톱 = 대화 · 진행 상황 · 예약 작업 · 스킬 · 연결된 앱 · 설정 / 관리자 = 개요 · 모델 · 카탈로그 · 승인 기록 · 트레이스 · 사용자·예산 · 설정 (+ 문서, ADR-0008).
  - E2E: Playwright, **기능 개발이 끝난 시점에** 작성·실행(= 금요일 데모). 기능이 없는 P0 은 증거(CI run · 두 PC `/start` 3줄)로 판정.
  - 렌더러: Vite + React 에 프로토타입 CSS 를 옮긴다. shadcn/ui · assistant-ui · React Flow 는 그 메뉴를 구현할 때 들인다.
  - 데스크톱 보안: `app://` 프로토콜 + CSP · contextIsolation · sandbox · 원격 요청 차단 · 권한 요청 거부 · 키 없음.
  - 버전(게시 7일 규칙): Electron 44.9.3 · Playwright 1.64.1 · Vite 8.3.5 · React 19.3.1 · TypeScript 6.0.3 · Node 24.22.1 (`.nvmrc` · `package-lock.json`).
- roadmap 에서 바뀐 것: P1-1·P1-4 웹 → 데스크톱 · P1-5 추가(메뉴 골격) · P2 = 관리자 기능 + 설치본 · rule 에 P0 증거 판정. 옛 문구는 git 이력.
- 미룸: 설치본·호스팅(P2) · 서명·자동 업데이트(P6) · 배포판 백엔드(로컬 sidecar vs 호스팅, P2 전에 결정) · 사용자 웹 앱(데스크톱 다음).
- 재검토: Playwright `_electron` 이 데스크톱 E2E 를 2주 이상 막을 때.
