# ADR-0015 · 파일 = conductor 가 저장 · 모델마다 서버가 전달 방법을 정하고 화면에 그대로 보인다

- 상태: 확정 · 2026-11-03 (사용자: 대화 + 프로젝트 + 스페이스 화면 · Office 까지 · 한 세션에서 차례대로)
- 맥락: 첨부 버튼이 '준비 중'. 모델마다 받는 형식이 다르고(이미지 · PDF 원본 · 글만), 큰 파일을 매 턴 다시 보내면 토큰이 크게 는다 (slice 05 토큰 다이어트와 같은 원칙).
- 결정
  - 저장: conductor 데이터 폴더에 sha256 이름으로 한 번만 · `files` · `file_chunks` 표 (표 추가 = SCHEMA_VERSION 그대로). 데스크톱은 파일 id 만 보낸다 (바이트를 대화 요청에 싣지 않는다).
  - 형식 판정 = 앞 바이트 · Office 는 표준 zipfile + XML (새 의존성 없음 · 압축 푼 크기 · 항목 수 상한 · DOCTYPE 거절) · PDF 글 = pypdf 하나만 추가.
  - 전달 = 서버 `files.plan(model, file)` 한 곳: 원본(vision · pdf_input 모델) / 글 / 앞부분 + `read_file`. 화면 칩은 이 결과를 그대로 보인다 (차별점: 보내기 전에 어떻게 가는지 · 몇 토큰인지).
  - 지난 턴 원본은 다시 안 보낸다 (이름 한 줄 + read_file). read_file 은 파일이 있는 대화에만 실린다 = hello 바이트 그대로.
- 탈락: 제공사 Files API 업로드(제공사마다 다름 · 키 · 보관 위치 분산) · Office 라이브러리 3~4개(공격면 · 크기) · 임베딩 검색(지금은 쪽 · 검색어 읽기로 충분 · 나중) · 클라이언트가 base64 로 바이트 전송.
- 재검토: 임베딩 검색이 필요할 때 · 스캔 PDF(OCR) · 음성 · 영상 파일.
